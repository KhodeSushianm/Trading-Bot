## ۰) 🔀 تغییر مسیر پروژه (v0.22.0) — فقط اندروید

**نسخهٔ ویندوز در `v0.21.0` منجمد شد.** تصمیم مالک پروژه: توسعه فقط روی اندروید.

| | قبل | بعد |
|---|---|---|
| خروجی قابل‌توزیع | setup.exe + EXE پرتابل + APK | **فقط APK** |
| `build-release.yml` | تست + بیلد ویندوز + انتشار | **فقط job تست** (پایتون + ۸ اسموک JS) |
| مالک نام/متن ریلیز | ورک‌فلو ویندوز | **ورک‌فلو اندروید** |
| `permissions` آن ورک‌فلو | `contents: write` | `contents: read` (اصل کمینه‌بودن دسترسی) |
| برنچ پیش‌فرض | `main` | **`ANDROID`** |
| برنچ‌ها | `main` + `android` | `main` + `ANDROID` + `android` (هر سه همگام؛ به تصمیم مالک حذف نشدند) |
| اجرای CI در هر push | ۶ ران (~۵٫۶ دقیقه) | **۲ ران روی `ANDROID` + ۱ نگهبان ارزان** — تست و بیلد فقط روی برنچ اصلی، چون سه برنچ همیشه روی یک کامیت‌اند |
| نگهبان واگرایی | نداشت | `branch-sync.yml` — آینهٔ جلوتر (کد تست‌نشده) = شکست سخت؛ آینهٔ عقب‌تر = هشدار؛ هر ۶ ساعت هم زمان‌بندی‌شده |

### ⚠️ چرا موتور پایتون حذف نشد (مهم‌ترین نکتهٔ این بخش)

«انجماد ویندوز» با «حذف پایتون» یکی نیست. موتور پایتون سه نقش حیاتی برای
**خودِ اپ اندروید** دارد و حذفش تور ایمنی را نابود می‌کرد:

| نقش | مدرک |
|---|---|
| **اوراکلِ درستیِ محاسبات موتور JS** | `tests/js/gen_fixtures.py` دوازده ماژول پایتون را `import` می‌کند تا فیکسچرِ **۲۴ تست برابری** ساخته شود. بدون آن، هیچ چیز درست محاسبه‌شدنِ موتور اندروید را نمی‌سنجد. |
| **منبع حقیقتِ توکن‌های رنگ** | `smoke_theme_parity.js` فایل `src/ui/theme.py` را می‌خواند و ۴۱ توکن `style.css` را با آن مقایسه می‌کند (۲۱۱ بررسی). |
| **منبع حقیقتِ نسخه** | `android/app/build.gradle` و `build-android.yml` هر دو `APP_VERSION` را از `src/app_paths.py` می‌خوانند. |

موتور پایتون **Qt-free** است (تنها استثنا `src/report/sharecard.py`)، پس
نگه‌داشتنش سربار ویندوزی ندارد. لایهٔ UI ویندوز (`panel.py` + `src/ui/` +
`installer/` ویندوزی ≈ ۵٬۷۰۰ خط) منجمد است ولی **حذف نشد** — حذفش یعنی از دست
رفتن منبع حقیقت تم، مگر اینکه ابتدا `theme.py` به جای دیگری منتقل شود.

## ۱) برنامه چیست؟

**ODIN Assistant** دستیار تحلیل و سیگنال‌دهی فارکس و طلا است که بازار را از چهار منبع
دادهٔ **رایگان و بدون کلید API** می‌سنجد (تکنیکال + فاندامنتال + اخبار + تاییدیهٔ
تریدینگ‌ویو)، با یک **داور امتیازدهی** (۷ دروازهٔ وتو + ۸ مدرک از ۱۱ امتیاز) فقط
سیگنالِ دارای پشتوانه صادر می‌کند و نتیجهٔ هر سیگنال را در **ژورنال صداقت** ثبت و
پیگیری می‌کند. همهٔ خروجی‌ها فارسی، با دلایل کامل — «چرا سیگنال ندادیم» به همان
اندازهٔ «چرا دادیم» گزارش می‌شود.

**دو پلتفرم فعال:**

| پلتفرم | وضعیت | انتشار |
|---|---|---|
| 🖥️ **ویندوز ۱۰/۱۱** (PySide6) | پنل ۸ صفحه‌ای + تلگرام + حلقهٔ خودکار + نصب‌کنندهٔ رسمی | `v0.21.0` |
| 📱 **اندروید ۷.۰+** (WebView + موتور JS) | همان مغز، در جیب — با **رصد پس‌زمینه** (سیگنال بدون باز کردن اپ) | `v0.21.0` |

**از v0.19.0 دو پلتفرم یک درخت کد دارند** (برنچ‌های `main` و `android` هم‌اکنون روی یک
کامیت‌اند) و **از v0.20.1 یک تگ، هر دو خروجی را می‌سازد**: نصب‌کنندهٔ ویندوز + EXE
پرتابل + APK امضاشده، همه روی یک Release.

**سیستم لایسنس و قفل دستگاه** (v0.14.0) و **دورهٔ آزمایشی ۷ روزه + لایسنس زمان‌دار**
(v0.15.0) روی هر دو پلتفرم فعال‌اند.

**سه اصل طراحی که تا امروز نقض نشده‌اند:**

| اصل | معنی عملی |
|---|---|
| **غیرخودکار** | هیچ معامله‌ای اجرا نمی‌شود؛ حتی به متاتریدر/بروکر وصل نیست. خروجی پیشنهاد است. |
| **صداقت اول** | مدرکِ بدون داده صادقانه ۰ می‌گیرد؛ دلیل هر وتو مکتوب است؛ ژورنال بدون روتوش گزارش می‌شود. |
| **هزینهٔ صفر** | بدون سرور، بدون اشتراک، بدون کلید پولی؛ زاپاس خودکار وقتی منبعی قطع شود. |

        EMA·ADX·RSI·ATR·سطوح      تقویم+ترجمهٔ فارسی     اهمیت ۰..۶+جهت اثر
        قدرت ۸ ارز · تاییدیهٔ TV       │                    │
                └──────────┬───────────┴────────────────────┘
                           ▼

### اندروید (v0.21.0)

```
┌───────────────────────────── APK (~0.38MB) ─────────────────────────────┐
│ MainActivity — WebView تمام‌صفحه (رابط ۸ صفحهٔ RTL، آیکون‌های SVG)        │
│ OdinService  — رصد پس‌زمینه: WebView بی‌سر (?svc=1) روی همان موتور؛      │
│                زمان‌بندی چرخه‌ها نیتیو (Handler) چون تایمر JS در          │
│                پس‌زمینه کشته می‌شود؛ اعلان ماندگار + دکمهٔ توقف           │
│ BootReceiver — بازگرداندن رصد بعد از ریستارت گوشی                        │
│ Bridge/Notif — HTTP بدون CORS · SharedPreferences مشترک (ژورنال/ضداسپام/ │
│                state.last یکی است → اعلان تکراری نمی‌رود) · اعلان‌ها      │
│ assets/www   — fa·icons·config·indicators·session·technical·calendar·    │
│                news·judge·journal·data·alerts·chart·sharecard·briefing·   │
│                components (Aurora)·ui·app                                │
└──────────────────────────────────────────────────────────────────────────┘
```

**لایهٔ بصری (v0.21.0):** `style.css` همهٔ ۴۱ توکن `theme.py` را دارد و
`js/components.js` همتای ۸ ویجت `src/ui/widgets.py` است — پس زبان بصری دو پلتفرم
یکی است و `smoke_theme_parity.js` واگرایی‌شان را قرمز می‌کند.

**چرا این طراحی؟** موتور JS پورت خط‌به‌خط پایتون است و با ۲۴ تست برابری قفل شده؛
رشته‌های موتور عمداً دست‌نخورده‌اند و تبدیل‌های نمایشی (مثل ایموجی→آیکون در v0.13.0)
فقط در لایهٔ رندر انجام می‌شود — پس دو پلتفرم همیشه هم‌نتیجه می‌مانند.

### ویندوز

پنل PySide6 (۸ صفحه)، حلقهٔ زمان‌بند، تلگرام (بریفینگ/سیگنال/هشدار/خلاصهٔ شبانه)،
نصب‌کنندهٔ Inno Setup با منطق پوشهٔ دادهٔ ۴ حالته (پرتابل/نصب‌شده/env/legacy)،

صفحهٔ ورود (`onboarding.py`)، ۸ ویجت ساختاریافته (`widgets.py`) و تم ۴۱ توکنی.

### ✅ ۱. (رفع شد) پنل ویندوز روی ماشینِ بدون لایسنس **کرش می‌کرد** (بحرانی — بلاکر انتشار)

RuntimeError: libshiboken: '__init__' method of object's base class (MainWindow) not called.

### ✅ ۳. (رفع شد) اعتبارسنجی لایسنس تشریفاتی بود

`validate_license()` هر رشتهٔ ≥۱۶ کاراکتر را **معتبر** می‌داند — هیچ امضا/HMAC/سروری
در کار نیست؛ `generate_license_key()` (SHA256 دلخواه) هم به هیچ‌وجه به اعتبارسنجی وصل
نیست. یعنی هر کاربری با تایپ ۱۶ کاراکتر دلخواه برنامه را فعال می‌کند. قفل دستگاه
(تطبیق `device_id`) فقط جلوی «کپی فایل license.dat» را می‌گیرد، نه جلوی فعال‌سازی
خودخدمت. برای محصول پولی، حداقلِ لازم: کلید = `HMAC(secret, device_id)` که سمت
سازنده تولید و سمت اپ با secret امضاشده راستی‌آزمایی شود (یا فعال‌سازی آنلاین).
**رفع انجام‌شده:** طرح کامل HMAC پیاده شد — `key = HMAC-SHA256(SECRET, device_code)`؛
اعتبارسنجی با `hmac.compare_digest` (ضد timing)؛ `generate_license_key` اکنون
ابزار سمت سازنده است (`python -m src.license gen CODE`)؛ بُرِدهای آزمایشی مشترک
پایتون/JS در `main.py --selftest` و `tests/js/smoke_license.js` قفل شدند
(sha256/hmac جاوااسکریپت با `node:crypto` روی طول‌های مرزی padding مقایسه شد).
محدودیت ذاتی لایسنس آفلاین (secret در باینری) صادقانه در `LICENSE_GUIDE.md` مستند است.

### ✅ ۴. (رفع شد) باگ‌های `get_device_id()`

* مسیر لینوکس `os.ifaddresses`/`os.AF_LINK` صدا می‌زند — چنین API در ماژول `os` نیست
  (مال `psutil` است) → همیشه استثنا می‌خورد و بی‌صدا به fallback می‌رود.
* مسیر ویندوز `wmic` است که در بیلدهای تازهٔ ویندوز ۱۱ **حذف شده** → آنجا هم fallback.
* fallback مشترک `uuid.getnode()` است (MAC) — روی ماشین‌های چند-NIC/VPN می‌تواند
  بین اجراها عوض شود → کاربرِ واقعی قفلش می‌پرد.
**رفع انجام‌شده:** شناسه به «پایدارترین منبع هر پلتفرم» تغییر کرد — ویندوز:
MachineGuid از رجیستری با `winreg` (بدون wmic) و زاپاس PowerShell CIM؛ لینوکس:
machine-id؛ مک: IOPlatformUUID؛ اندروید: ANDROID_ID (سمت Bridge، SHA-256 در جاوا).
MAC فقط آخرین چاره است. قطعی‌بودن با `tests/manual/test_license.py` تست شد.
(یک باگ padding هم در sha256 جاوااسکریپت هنگام همین تست‌ها کشف و رفع شد:
طول‌های l≡55 mod 64 — وکتورها حالا با node:crypto مو‌به‌مو برابرند.)

### ✅ ۱. (رفع شد) دو نسخهٔ پیاپی **بدون APK** منتشر شدند — `v0.19.1` و `v0.20.0`

مدرک از API گیت‌هاب (نه حدس):

```
v0.20.0  Build Android APK  →  job "build" = skipped
v0.19.1  Build Android APK  →  job "build" = skipped
v0.19.0  Build Android APK  →  job "build" = success
```

**دو علت مستقل که روی هم افتادند:**
* `build-android.yml` فقط `upload-artifact` می‌کرد و **هرگز** فایل را به Release
  نمی‌چسباند. APKهای v0.16→v0.19 همه **دستی** آپلود شده بودند (`uploader=KhodeSushianm`).
  یعنی انتشار به یک انسان وابسته بود — و دو بار جا افتاد.
* نگهبانِ تگ فقط refs قابل‌دسترس از برنچ `android` را قبول می‌کرد. اما از v0.19.0
  دو پلتفرم یک درخت کد دارند و `android/` روی `main` هم هست؛ پس تگ‌های `main`
  **بی‌صدا** skip می‌شدند.

**پیامد:** کاربر اندروید دو نسخهٔ پیاپی را نتوانست دانلود کند، و هیچ هشداری هم
در کار نبود (run سبز گزارش می‌شد چون jobِ skipped = success).
**رفع:** نگهبان حالا تگِ قابل‌دسترس از `android` **یا** `main` را می‌پذیرد؛ مرحلهٔ
«Publish APK to GitHub Release» با `gh` فایل را می‌چسباند (با ساخت ریلیز در صورت نبود
و retry برای رقابت با ورک‌فلو ویندوز)؛ و اگر تگ زده شود ولی APK امضانشده تولید
نشود، ورک‌فلو با `::error` می‌شکند. **راستی‌آزمایی:** v0.20.1 و v0.21.0 هر دو APK
از CI منتشر کردند.

```

قابل تایپ توسط کاربر  : 8D8D-32C8-5C9E-AD32-2612     (۲۴ نویسه / ۲۰ هگز)

```

**پیامد:** قابلیت «لایسنس زمان‌دار / مدل اشتراکی» که در v0.15.0 اضافه شده بود،

(`parseKeyInput` با ورودی کامل) و هرگز نمی‌پرسد «آیا **رابط کاربری** می‌تواند آن
ورودی کامل را تولید کند؟». این یک **شکافِ دسته‌ای** است نه یک مورد: هر جا
«موتور» و «رابط» جدا تست شوند، ناسازگاریِ بینشان دیده نمی‌شود.
**رفع:** گروه ۲ `smoke_onboarding.js` سرتاسری می‌سنجد — کلید واقعی تولید
می‌کند، قالب‌دهی می‌کند، **به اندازهٔ maxlength می‌بُرد**، سپس parse/validate.
