## ۱) برنامه چیست؟

**ODIN Assistant** دستیار تحلیل و سیگنال‌دهی فارکس و طلا است که بازار را از چهار منبع
دادهٔ **رایگان و بدون کلید API** می‌سنجد (تکنیکال + فاندامنتال + اخبار + تاییدیهٔ
تریدینگ‌ویو)، با یک **داور امتیازدهی** (۷ دروازهٔ وتو + ۸ مدرک از ۱۱ امتیاز) فقط
سیگنالِ دارای پشتوانه صادر می‌کند و نتیجهٔ هر سیگنال را در **ژورنال صداقت** ثبت و
پیگیری می‌کند. همهٔ خروجی‌ها فارسی، با دلایل کامل — «چرا سیگنال ندادیم» به همان
اندازهٔ «چرا دادیم» گزارش می‌شود.

**دو پلتفرم فعال:**

| پلتفرم | وضعیت | انتشار |
|---|---|---|
| 🖥️ **ویندوز ۱۰/۱۱** (PySide6) | پنل ۸ صفحه‌ای + تلگرام + حلقهٔ خودکار + نصب‌کنندهٔ رسمی | `v0.8.1` (برنچ `main`) |
| 📱 **اندروید ۷.۰+** (WebView + موتور JS) | همان مغز، در جیب — با **رصد پس‌زمینه** (سیگنال بدون باز کردن اپ) | `v0.13.0` (برنچ `android`) |

از v0.14.0 (در جریان) **سیستم لایسنس و قفل دستگاه** برای عرضهٔ تجاری مستقیم اضافه شده —
که در بخش «مشکلات جاری» همین گزارش، وضعیت واقعی آن مستند است.

**سه اصل طراحی که تا امروز نقض نشده‌اند:**

| اصل | معنی عملی |
|---|---|
| **غیرخودکار** | هیچ معامله‌ای اجرا نمی‌شود؛ حتی به متاتریدر/بروکر وصل نیست. خروجی پیشنهاد است. |
| **صداقت اول** | مدرکِ بدون داده صادقانه ۰ می‌گیرد؛ دلیل هر وتو مکتوب است؛ ژورنال بدون روتوش گزارش می‌شود. |
| **هزینهٔ صفر** | بدون سرور، بدون اشتراک، بدون کلید پولی؛ زاپاس خودکار وقتی منبعی قطع شود. |

## ۸) مشکلات جاری (راست‌آزمایی‌شده در همین بازبینی) — مربوط به v0.14.0

> این بخش به سبک «صداقت اول» پروژه نوشته شده: مشکلات کاری که هنوز در جریان است
> با مدرک مستند می‌شود تا قدم بعدی دقیق باشد.

### 🔴 ۱. پنل ویندوز روی ماشینِ بدون لایسنس **کرش می‌کند** (بحرانی — بلاکر انتشار)

بررسی لایسنس در `panel.py` **قبل از** `super().__init__()` قرار گرفته و دیالوگ فعال‌سازی
`QDialog(self)` را با آبجکتِ هنوز ساخته‌نشده والد می‌سازد. خروجی واقعی روی ماشین تمیز:

```
File "panel.py", line 188, in __init__
    if not self._show_activation_dialog():
File "panel.py", line 904, in _show_activation_dialog
    dialog = QDialog(self)
RuntimeError: libshiboken: '__init__' method of object's base class (MainWindow) not called.
```

**پیامد:** (الف) کاربر تازه‌نصب‌شده به‌جای دیالوگ فعال‌سازی، کرش می‌بیند — دقیقاً
مسیری که لایسنس برای آن ساخته شده؛ (ب) `panel.py --selftest` می‌شکند → اولین بیلد
ویندوزِ تگ‌شده از main (مرحلهٔ «panel selftest» در `build-release.yml`) قرمز خواهد شد؛
(ج) تست دستی `test_gui_integration` هم همین کرش را می‌خورد.
**رفع پیشنهادی:** انتقال چک لایسنس به بعد از `super().__init__()` (یا ساخت دیالوگ بدون
والد) + bypass در حالت `--selftest` (مثل `ODIN_SKIP_LICENSE=1`).

### 🔴 ۲. ورک‌فلو `build-android.yml` در همهٔ اجراها (۱۰+، شامل ۴ اصلاحیهٔ پیاپی) شکست خورده

خطای واقعی از لاگ CI:

```
Minimum supported Gradle version is 8.7. Current version is 8.5.
```

ورک‌فلو Gradle 8.5 نصب می‌کند در حالی که AGP پروژه 8.5.2 حداقل Gradle 8.7 می‌خواهد.
علاوه بر آن، حتی اگر سبز شود **خروجی قابل توزیع نیست**:
* APK **debug** با keystore یک‌بارمصرف CI امضا می‌شود → با کلید رسمی
  (`bd11159e…`) نمی‌خواند → کاربران نمی‌توانند درجا آپدیت کنند (نقض زنجیرهٔ امضا).
* روی **همهٔ تگ‌های `v*`** اجرا می‌شود، حتی تگ‌های ویندوزیِ برنچ main.
* «قفل لایسنس» که در پیام کامیت آمده، در خود ورک‌فلو وجود ندارد.

**مسیر درست:** ساخت **release** با Gradle ≥8.7، و یا (الف) keystore رسمی در
GitHub Secrets + امضای امن در CI، یا (ب) ادامهٔ ساخت محلی مثل v0.9→v0.13
(که امتحان خود را پس داده). الگوی بیلد محلی موفق، مستندِ `docs/android-fa.md` است.

### 🟠 ۳. اعتبارسنجی لایسنس تشریفاتی است

`validate_license()` هر رشتهٔ ≥۱۶ کاراکتر را **معتبر** می‌داند — هیچ امضا/HMAC/سروری
در کار نیست؛ `generate_license_key()` (SHA256 دلخواه) هم به هیچ‌وجه به اعتبارسنجی وصل
نیست. یعنی هر کاربری با تایپ ۱۶ کاراکتر دلخواه برنامه را فعال می‌کند. قفل دستگاه
(تطبیق `device_id`) فقط جلوی «کپی فایل license.dat» را می‌گیرد، نه جلوی فعال‌سازی
خودخدمت. برای محصول پولی، حداقلِ لازم: کلید = `HMAC(secret, device_id)` که سمت
سازنده تولید و سمت اپ با secret امضاشده راستی‌آزمایی شود (یا فعال‌سازی آنلاین).

### 🟠 ۴. باگ‌های `get_device_id()`

* مسیر لینوکس `os.ifaddresses`/`os.AF_LINK` صدا می‌زند — چنین API در ماژول `os` نیست
  (مال `psutil` است) → همیشه استثنا می‌خورد و بی‌صدا به fallback می‌رود.
* مسیر ویندوز `wmic` است که در بیلدهای تازهٔ ویندوز ۱۱ **حذف شده** → آنجا هم fallback.
* fallback مشترک `uuid.getnode()` است (MAC) — روی ماشین‌های چند-NIC/VPN می‌تواند
  بین اجراها عوض شود → کاربرِ واقعی قفلش می‌پرد. (تست عملی: اجرای `python src/license.py`
  روی همین ماشین، شناسه را فقط از fallback تولید کرد.)

### 🟡 ۵. اپ اندروید هیچ قفل لایسنسی ندارد

راهنمای لایسنس فقط مسیرهای دسکتاپ را می‌گوید و کد JS/Java اپ دست نخورده است؛
APK رسمی v0.13.0 آزادانه کپی/نصب می‌شود. اگر سیاست فروش، قفل هر دو پلتفرم است،
باید طراحی شود (پیشنهاد: همان HMAC با device-id اندروید = `Settings.Secure.ANDROID_ID`
یا Build-based fingerprint).

### 🟡 ۶. تگ `v0.14.0` بدون ریلیز وجود دارد

مثل تجربهٔ v0.13.0، تگ زده شده ولی ریلیز/آرتیفکتی ندارد و CI اندرویدش قرمز است.
تا رفع موارد بالا، ریلیز v0.14.0 منتشر **نشود** (و اگر ورک‌فلو اندروید با debug-keystore
سبز هم شود، APK آن توزیع نشود).
