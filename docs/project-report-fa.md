## ۱) برنامه چیست؟

**ODIN Assistant** یک دستیار تحلیل و سیگنال‌دهی فارکس و طلا برای ویندوز است که روی
کامپیوتر شخصی کاربر اجرا می‌شود. بازار را از چهار منبع دادهٔ **رایگان و بدون کلید API**
تحلیل می‌کند (تکنیکال + فاندامنتال + اخبار + تاییدیهٔ تریدینگ‌ویو)، به هر فرصت معاملاتی
با یک **داور امتیازدهی** نمرهٔ پشتوانه می‌دهد و فقط سیگنال‌های معتبر را — با دلایل کامل
به زبان فارسی ساده، شامل ورود/حدضرر/هدف و فهرست مدارکی که امتیاز نگرفته‌اند — روی
تلگرام ارسال می‌کند.

سه اصل طراحی که از روز اول تا همین‌جا بدون استثنا رعایت شده‌اند:

| اصل | معنی عملی در کد |
|---|---|
| **غیرخودکار** | سیستم هیچ معامله‌ای اجرا نمی‌کند؛ حتی به متاتریدر وصل هم نیست. خروجی، پیشنهاد است نه دستور. |
| **صداقت اول** | «چرا سیگنال ندادیم» به همان اندازهٔ «چرا دادیم» گزارش می‌شود (حلقهٔ صداقت داور + ژورنال). مدرکی که داده نداشته، صادقانه ۰ می‌گیرد و علامت ❔ می‌خورد. |
| **هزینهٔ صفر** | بدون سرور، بدون اشتراک، بدون کلید پولی. همهٔ منابع داده رایگان‌اند و در صورت قطع شدن منبع اصلی، زاپاس خودکار فعال می‌شود. |

- **۸ مدرک امتیازی** (جمع ۱۱): هم‌راستایی روند H4/H1 (۲)، واکنش به سطح کلیدی (۲)،
  پنجرهٔ فاندامنتال پاک (۲)، مومنتوم RSI (۱)، جریان قدرت ارزها (۱)، تایید خبری (۱)،
  هم‌جهتی تریدینگ‌ویو (۱)، سشن مناسب (۱). آستانهٔ صدور: **۷ از ۱۱**.
- **ریاضی ریسک:** SL از سطح کلیدی + بافر ATR با سقف/کف فاصله (جلوگیری از استاپ نویزی و

## ۵) کیفیت: تست‌ها و CI

### خودآزمون‌ها (در CI روی هر push)

| فرمان | پوشش |
|---|---|
| `python main.py --selftest` | پارس تقویم، قطبیت شاخص‌ها، ۹ حالت جهت‌دهی اخبار، ۶ وتو، ریاضی SL/TP، سقف سیگنال، ژورنال، کدگذاری کنسول ویندوز |
| `python panel.py --selftest` | ساخت پنل offscreen، ۸ صفحه، فونت، آیکون‌ها، داور/رندر |
| `python tests/check_config.py` | اعتبار `config.yaml` (۲۳ بررسی روی بخش judge و کلیدها) |
| `python tests/manual/test_paths_install.py` | منطق پوشهٔ داده: پرتابل / نصب‌شده / env / legacy (۸ تست) |

### سوئیت‌های دستی (امروز همه پاس شدند)

`test_judge` (داور در ۹ بخش)، `test_journal` (نتیجه‌یابی از کندل + آمار)،
`test_veto_report`، `test_news_direction`، `test_audit_fixes` (رگرسیون ۱۰ باگ ممیزی)،
`test_gui_integration`، `test_pages_render` (باگ «صفحهٔ سیاه/خالی»)، `test_layout_fit`
(چیدمان در اندازه‌های مختلف پنجره)، `test_paths_install`.

### خط لولهٔ CI (`build-release.yml`)

- **جاب `test`** (اوبونتو، هر push/PR): خودآزمون‌ها + اعتبار کانفیگ + کامپایل بایت‌کد.
- **جاب `build-windows`** (ویندوز، فقط تگ `v*` یا dispatch): stamp نسخه روی VERSIONINFO →
  selftest پنل → PyInstaller → اسموک EXE → بیلد نصب‌کنندهٔ Inno Setup →
  **اسموک‌تست نصب/حذف خاموش** → تغییر نام آرتیفکت → انتشار Release.

### دو دام واقعی اینو ستاپ که در همین بازبینی کشف و مستند شدند

1. اگر پوشهٔ مسیر `/LOG=` وجود نداشته باشد، Setup بی‌صدا با «failed to initialize»
   (کد ۱) خارج می‌شود و هیچ فایلی نمی‌سازد — علت شکست‌های پیابی اسموک‌تست همین بود؛
   اصلاحش (ساخت پوشه قبل از اجرا + `-PassThru` و بررسی کد خروج زودهنگام) در جریان است.
2. در تعویض سطح دسترسی، اینو ستاپ فرزند detached می‌سازد؛ پس معیار درست، poll روی
   فایل‌های نصب است نه کد خروج فرآیند پدر.

## ۶) داده‌ها، امنیت و حریم خصوصی

- **منطق پوشهٔ داده (`app_paths.data_dir`)** به ترتیب اولویت: متغیر `ODIN_DATA_DIR` ←
  وجود فایل `.portable` کنار EXE ← نشانگر `.installed` (حالت نصب‌شده) →
  `%APPDATA%\ODIN Assistant` ← فولدر EXE اگر نوشتنی باشد (legacy).
- **توکن تلگرام هرگز در ریپو نیست:** در پنل ذخیره می‌شود (پوشهٔ دادهٔ کاربر) یا
  `config.local.yaml` که در `.gitignore` است. `config.yaml` ریپو فقط قالب است.
- نصب برای کاربر جاری پیش‌فرض است (`PrivilegesRequired=lowest`) → بدون UAC؛ حذف تمیز
  شامل پاک‌کردن میان‌برها و نشانگرهاست.
- هیچ کتابخانهٔ ناشناس/باینری پیش‌ساخته‌ای در ریپو نیست؛ EXE فقط توسط GitHub Actions
  از همین سورس ساخته می‌شود.
